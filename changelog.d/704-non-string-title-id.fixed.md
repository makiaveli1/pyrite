- **A `title:` that YAML reads as a number, boolean or date is indexed under its own id (#704).** The title is now stringified once, where the file is loaded, so the id, the stored title and `get` agree: `title: true` → id `true`, stored title `"true"` (not SQLite's `"1"`); `title: 2024` → `2024`; `title: 1e3` → `1000-0`. Two limits are part of the design: the id comes from the value YAML parsed, not the source text, so spellings that parse equal (`1.10` and `1.1`, `1e3` and `1000.0`) collide — `ids missing` reports the collision; and titles YAML reads as `false`, `0` or `0.0` used to fall through the empty-title check to the `entry-da39a3ee` hash and now use their own slug (`false`, `0`, `0-0`). A `title:` that is a list, mapping or NaN still gets no id: loading refuses it with a named reason, the ids and index paths skip the file, and `pyrite qa` reports it (#711).
